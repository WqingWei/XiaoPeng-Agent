### 7.1 编写 `backend/core/safety_engine.py` ✅

**产出组件**：

| 组件 | 说明 |
|------|------|
| `SafetyEngine` | 加载并校验 `safety/rules.json`，构建规则上下文，逐条执行 12 条规则 |
| `SafetyResult` | 聚合 `safety_level`、`triggered_rules`、`required_actions`、`forbidden_actions` |
| `_ConditionEvaluator` | 基于 Python AST 的白名单条件求值器，不执行任意代码 |
| `UnsafeConditionError` | 非法或超出白名单的规则表达式异常 |

**核心行为**：

- 自动计算所有触发规则中的最高安全等级；无规则触发时返回 `L0`
- 将 `reject`、`warn`、`force`、`alert` 转换为明确的必需动作
- 根据升级配置补充“转人工”和“呼叫 110/120/119”动作
- `reject` 规则生成标准 `ForbiddenAction`，并渲染规则消息中的状态占位符
- 从现有 `VehicleState` 派生儿童座椅、驾驶员是否离座、后排儿童、目标温度等规则字段
- 允许 `intent` 以结构化字典补充订单、媒体、安全事件、剩余里程等运行时上下文
- 从用户消息识别乘客求助信号，供 S04 使用

### 7.2 实现安全条件求值器 ✅

支持正式计划与现有规则需要的表达式：

- 比较：`>`、`>=`、`<`、`<=`、`==`、`!=`
- 逻辑：`and`、`or`、`not`
- 字段路径：如 `driver.fatigue_level`、`vehicle.battery.charging`
- JSON 常量：`true`、`false`、`null`
- S10 续航公式所需的基础算术：`+`、`-`、`*`、`/`
- 缺失字段安全地按“不触发”处理
- 禁止函数调用、下标访问、lambda、私有属性等非白名单语法

**`backend/core/user_profile_manager.py`**：

**`backend/core/intent_engine.py`**：

- 新增 `IntentResult`：意图、类型、置信度、上下文因素、原始消息、实体

### 8.4 服务编排与工具执行 ✅

**`backend/core/orchestrator.py`**：

- 新增 `OrchestrationPlan`，在 `ServicePlan` 基础上携带工具选择理由、替代方案和确认信息
- 新增 `ToolResult`，记录每步成功状态、输出、错误、跳过状态和执行耗时
- LLM 规划结果会经过后置校验：
  - 丢弃不存在的工具
  - 过滤未知参数并检查必填参数
  - 重排 step_id 并修复依赖关系
  - 未确认时不执行 `modify_order` / `cancel_order`

- 工具异常时回滚到该步骤执行前状态
- 因现有工具使用全局 `ToolContext`，执行器增加异步锁，防止多会话并发串线
- 工具执行完成后将车辆、环境、订单和画像同步回当前会话
- LLM 不可用时，本地降级规划可闭环执行 8 个标准场景

## 步骤十七后续优化：持久化会话记忆

**执行时间**：2026-08-07
**执行状态**：✅ 功能与本地生产环境验证完成，改动待提交

根据 Web 体验复核结果，将原有“单进程、固定 session ID”的短期记忆升级为标签页级独立
会话、刷新恢复和 PostgreSQL/Redis 持久化。PostgreSQL 作为完整上下文与用户画像的持久
真源，Redis 作为读缓存；未配置外部存储时仍可回退到原内存模式，保证现有开发和测试流程
兼容。

### A. 标签页级独立会话 ID ✅

- 移除前端硬编码的 `xpeng-demo-session`
- 首次打开页面时使用 `crypto.randomUUID()` 生成 `xpeng-<uuid>` 会话 ID
- 会话 ID 保存到 `sessionStorage`：同一标签页刷新后保持不变，不同标签页使用独立 ID
- 浏览器禁用 `sessionStorage` 时自动退化为当前页面生命周期内的随机 ID
- 会话初始化完成前禁用聊天、场景选择和模式切换，避免向后端提交空 session ID

### B. 页面刷新后的历史恢复 ✅

- 页面启动时调用 `GET /api/state/{session_id}` 拉取完整会话快照
- 恢复当前模式、场景、高亮状态、车辆、环境、订单与最近 100 条消息
- `ConversationMessage` 新增可选 `agent_response`，后端在保存助手回复时同时保存完整
  `AgentResponse`
- 前端水合历史消息后，自动恢复最后一轮“决策详情”；历史回复仍可点击“查看详情”
- REST 恢复完成后才建立当前 session 的 Socket.IO 监听，避免刷新期间的跨会话事件串线

### C. PostgreSQL 真源与 Redis 缓存 ✅

新增 `PostgresRedisPersistence`：

- PostgreSQL 自动创建 `agent_sessions` 与 `user_profiles` 两张表，状态使用 JSONB 保存
- `agent_sessions` 保存消息、场景、轮次、车辆、环境、订单与会话画像完整快照
- `user_profiles` 以 `user_id` 保存可跨会话读取的用户偏好和历史
- Redis 使用 `xiaopeng:session:*` / `xiaopeng:profile:*` 键缓存同一 JSON 快照
- 读取顺序为 Redis → PostgreSQL → 创建默认上下文；PostgreSQL 命中后回填 Redis
- 写入顺序为 PostgreSQL upsert → Redis 更新，默认缓存 TTL 为 86400 秒
- 场景切换、场景取消、模式切换、状态更新、工具执行结果和每轮对话均会持久化
- `PERSISTENCE_REQUIRED=true` 时未配置或无法连接存储会阻止启动；原生开发默认允许内存回退
- 应用 lifespan 负责初始化连接、创建表和关闭连接池，不在模块导入阶段访问外部服务

### D. Docker 与部署配置 ✅

`docker-compose.yml` 从前后端两服务扩展为四服务：

| 服务 | 作用 | 持久化 |
|------|------|--------|
| `frontend` | Next.js Web UI | 无状态 |
| `backend` | FastAPI / Socket.IO / Agent | 通过 PostgreSQL/Redis |
| `postgres` | 会话与画像真源 | `postgres_data` 命名卷 |
| `redis` | 会话与画像读缓存 | AOF + `redis_data` 命名卷 |

- 后端等待 PostgreSQL 与 Redis 健康后启动，并在 Compose 中强制要求持久化可用
- `.env.example` 增加 `DATABASE_URL`、`REDIS_URL`、缓存 TTL 和 required 开关
- `render.yaml` 增加生产环境数据库/Redis URL 与 required 配置
- README、交付清单和模拟数据说明同步更新为持久化语义
