## 技术栈

| 层 | 技术 | 版本 | 用途 |
|---|------|------|------|
| 前端框架 | Next.js (App Router) | 14.x | SSR + API Routes |

| 容器化 | Docker + Docker Compose | — | 一键部署 |
| 代码规范 | 前端 ESLint+Prettier / 后端 Ruff | — | 统一代码风格 |

## 步骤一：环境准备与项目初始化

1. 创建后端目录并初始化 Python 项目

```bash
mkdir -p backend && cd backend
uv init --name xiaopeng-agent
```

2. 在 `backend/pyproject.toml` 中添加依赖

```toml
[project]
name = "xiaopeng-agent"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = [
    "fastapi>=0.110.0",
    "uvicorn[standard]>=0.27.0",
    "langchain>=0.2.0",
    "langchain-openai>=0.1.0",
    "openai>=1.0.0",
    "pydantic>=2.0.0",
    "python-socketio>=5.0.0",
    "python-dotenv>=1.0.0",
    "httpx>=0.27.0",
    "loguru>=0.7.0",
    "jinja2>=3.1.0",
    "pytest>=8.0.0",
    "pytest-asyncio>=0.23.0",
]
```

3. 安装依赖

```bash
cd backend && uv sync
```

4. 创建后端所有子目录

```bash
cd backend
mkdir -p config core tools models mock safety prompts/templates api tests
touch config/__init__.py core/__init__.py tools/__init__.py models/__init__.py mock/__init__.py safety/__init__.py prompts/__init__.py api/__init__.py
```

5. 创建 `backend/.env.example`

```env
OPENAI_API_KEY=sk-xxx
OPENAI_BASE_URL=https://api.openai.com/v1
MODEL_NAME=gpt-4o
MODEL_NAME_LITE=gpt-4o-mini
BACKEND_PORT=8000
LOG_LEVEL=INFO
```

6. 复制为 `.env` 并填入真实的 API Key

```bash
cp .env.example .env
```

7. 初始化前端项目（在另一个终端）

```bash
cd XiaoPeng-Agent
npx create-next-app@latest frontend --typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --use-pnpm
```

8. 安装前端额外依赖

```bash
cd frontend
pnpm add socket.io-client framer-motion zustand react-markdown lucide-react
pnpm add -D prettier @types/node
```

9. 初始化 shadcn/ui

```bash
cd frontend
npx shadcn@latest init
```

10. 添加需要的 shadcn 组件

```bash
npx shadcn@latest add button card input badge scroll-area separator tabs accordion
```

11. 初始化 Git

```bash
cd XiaoPeng-Agent
git init
```

12. 创建 `.gitignore`，内容包含

```
.env
node_modules/
.next/
__pycache__/
*.pyc
.venv/
dist/
```

## 步骤三：数据模型定义

每个模型文件用 Pydantic `BaseModel` 定义，字段参照需求文档第7章。

1. 编写 `backend/models/vehicle.py` — `VehicleState`

字段：`vehicle_id`(str)、`mode`(Literal["owner","robotaxi"])、`driving_status`(Literal["parked","driving","charging"])、`speed`(float)、`location`(含 lat/lng/address)、`battery`(含 level/range_km/charging/temperature)、`fuel`(含 level/range_km)、`cabin`(含 ac/seats/windows/child_lock/ambient_light)、`driver`(含 fatigue_level/driving_duration_min/lane_departure_count/eyes_detected)、`trip`(含 start_time/distance_km/avg_speed)。

2. 编写 `backend/models/order.py` — `OrderState`

字段：`order_id`、`status`(7种状态枚举)、`passenger`(含 user_id/name/phone/location)、`vehicle`(含 vehicle_id/model/color/plate/location)、`route`(含 pickup/dropoff/waypoints/estimated_distance_km/estimated_duration_min)、`pricing`(含 base_fee/distance_fee/time_fee/total)、`timestamps`(5个时间戳)。

3. 编写 `backend/models/user_profile.py` — `UserProfile`

字段：`user_id`、`name`、`role`(owner/passenger)、`preferences`(含 ac_temp_default/seat_position/music_genre/language/notifications)、`history`(含 frequent_destinations/recent_trips/charging_stations_used)、`context`(含 has_child/child_age/calendar_events)。

4. 编写 `backend/models/environment.py` — `EnvironmentContext`

字段：`weather`(含 condition/temperature/humidity/visibility_km)、`time`(含 current/period/is_holiday)、`traffic`(含 congestion_level/incidents列表)、`nearby`(含 charging_stations/service_areas/hospitals/parking_lots/restaurants)。

5. 编写 `backend/models/safety_rules.py` — `SafetyRule`

字段：`rule_id`(str)、`name`(str)、`type`(Literal["hard","soft"])、`trigger_condition`(str)、`action`(Literal["reject","warn","force","alert"])、`message_template`(str)、`escalation`(含 level/transfer_to_human/call_emergency)。

6. 编写 `backend/models/agent_output.py` — `AgentResponse`

完整结构参照需求文档第9章：包含 `timestamp`、`session_id`、`turn_id`、`user_response`、`service_plan`(含 summary/steps/total_estimated_time_s)、`reasoning`(含 detected_intent/intent_type/context_factors/tool_selection_reasons/alternatives_considered)、`forbidden_actions` 列表、`safety_alerts` 列表、`follow_up`(含 needs_confirmation/confirmation_message/suggested_replies)。

7. 在每个 model 文件中定义所有子模型类，如 `BatteryInfo`、`CabinState`、`SeatInfo` 等嵌套结构。

## 步骤六：工具箱实现

所有工具使用 LangChain `@tool` 装饰器，每个工具接收参数 → 更新 Mock 状态 → 返回执行结果 dict。

1. 编写 `backend/tools/base.py`

创建工具注册器 `ToolRegistry` 类，提供 `get_all_tools()` 方法返回所有已注册工具列表，供 LangChain Agent 使用。

2. 编写 `backend/tools/cabin_tools.py` — 6个工具

| 工具函数 | 参数 | 返回 |
|---------|------|------|
| `ac_control(zone, temp, fan_speed, mode)` | 区域/温度/风量/模式 | `{"success": true, "message": "已将驾驶位空调调至24°C"}` |
| `seat_control(seat_id, position, heating, cooling, massage)` | 座椅ID/位置/加热/通风/按摩 | 执行结果 |
| `window_control(window_id, action, level)` | 车窗ID/动作/开合度 | 执行结果 |
| `light_control(type, color, brightness)` | 灯光类型/颜色/亮度 | 执行结果 |
| `media_control(action, source, volume, content_id)` | 播放/暂停/切歌/音量 | 执行结果 |
| `child_lock(action)` | enable/disable | 执行结果（disable 时需检查后排有人则拒绝） |

每个工具内部：校验参数范围 → 检查安全约束 → 更新 `vehicle_mock` 中的状态 → 返回结果。

3. 编写 `backend/tools/navigation_tools.py` — 5个工具

| 工具函数 | 参数 | 返回 |
|---------|------|------|
| `navigate_to(destination, waypoints, preference)` | 目的地/途经点/偏好 | 导航路线信息 |
| `search_poi(category, keyword, radius, sort_by)` | 类别/关键词/半径 | POI 列表（从 poi_mock 查询） |
| `search_parking(location, radius, filter)` | 位置/半径 | 停车场列表 |
| `search_charger(location, radius, power_type, sort_by)` | 位置/功率类型 | 充电站列表 |
| `traffic_info(route_id)` | 路线ID | 路况信息 |

4. 编写 `backend/tools/vehicle_tools.py` — 4个工具

`get_vehicle_status()`、`get_driver_status()`、`get_location()`、`get_environment()` — 均无参数，返回当前 Mock 状态快照。

5. 编写 `backend/tools/order_tools.py` — 6个工具

`create_order(pickup, dropoff, vehicle_type)`、`modify_order(order_id, changes)`、`cancel_order(order_id, reason)`、`get_order_status(order_id)`、`locate_vehicle(order_id)`、`signal_vehicle(order_id, action)` — 操作 Mock 订单状态。

6. 编写 `backend/tools/safety_tools.py` — 5个工具

`emergency_stop()`、`call_rescue(type, location)`、`call_emergency(service)`、`transfer_human(priority, context)`、`safety_alert(level, message)` — 返回模拟的应急响应结果。

## 步骤七：安全规则引擎

1. 编写 `backend/core/safety_engine.py`

创建 `SafetyEngine` 类：

- `__init__()`: 加载 `safety/rules.json`，解析为 `SafetyRule` 对象列表
- `check(vehicle_state, environment, intent, user_message) -> SafetyResult`: 遍历所有规则，将 `trigger_condition` 字符串解析为 Python 表达式并在当前车辆/环境状态下求值。收集所有触发的规则，取最高安全等级，返回 `SafetyResult`（包含 `safety_level`、`triggered_rules` 列表、`required_actions` 列表、`forbidden_actions` 列表）

2. 实现条件求值器

将 `trigger_condition` 中的字段路径（如 `driver.fatigue_level`）映射到实际状态对象的属性值上。支持 `>`、`>=`、`<`、`==`、`and`、`or` 运算符。

3. 编写 `backend/tests/test_safety.py`

对12条规则逐条测试：构造触发条件满足的状态 → 调用 `check()` → 断言返回正确的安全等级和动作。再测试不触发时的反面情况。

## 步骤八：Agent 核心引擎

1. 编写 `backend/core/context_manager.py`

创建 `ContextManager` 类：

- 维护 `dict[session_id, ConversationContext]`，每个上下文包含：对话历史列表、当前车辆状态、当前环境、当前订单、用户画像
- `get_context(session_id)`: 返回或创建上下文
- `add_message(session_id, role, content)`: 追加消息
- `update_vehicle_state(session_id, state)`: 更新车辆状态
- `reset(session_id, scenario_id)`: 重置为场景预设状态

2. 编写 `backend/core/user_profile_manager.py`

创建 `UserProfileManager` 类，管理用户偏好加载和更新。

3. 编写 `backend/prompts/system_prompt.py`

创建 `build_system_prompt(mode, vehicle_state, environment, order, user_profile)` 函数：拼接系统 Prompt，内容包含 Agent 角色定义（小鹏AI出行服务管家）、当前模式、可用工具列表及参数描述（从 ToolRegistry 获取）、安全规则摘要、输出 JSON Schema 要求、当前车辆/环境/订单状态快照。

4. 编写 `backend/prompts/few_shot_examples.py`

为8个场景各编写2个 Few-shot 示例（一个正常、一个边界case），格式为 `[{"role": "user", "content": "..."}, {"role": "assistant", "content": "...(完整JSON输出)..."}]`。

5. 编写 `backend/prompts/templates/intent_analysis.j2`

Jinja2 模板，接收用户消息 + 上下文变量，生成意图分析 Prompt：要求 LLM 输出 JSON 包含 `detected_intent`、`intent_type`(explicit/implicit/urgent)、`confidence`(0-1)、`context_factors`。

6. 编写 `backend/prompts/templates/service_planning.j2`

要求 LLM 基于意图和安全约束，选择工具并生成执行计划：输出 JSON 包含 `steps`（每步含 tool/params/dependency/estimated_duration_s）、`tool_selection_reasons`、`alternatives_considered`。

7. 编写 `backend/prompts/templates/response_generation.j2`

要求 LLM 基于服务计划和工具执行结果，生成自然语言 `user_response`，要求温暖、专业、简洁。

8. 编写 `backend/core/intent_engine.py`

创建 `IntentEngine` 类：

- 使用 LangChain ChatOpenAI 初始化（从 settings 读取模型配置）
- `analyze(user_message, context) -> IntentResult`: 用 Jinja2 渲染 `intent_analysis.j2` 模板，调用 LLM，解析返回的 JSON 为 `IntentResult`（含 detected_intent/intent_type/confidence/context_factors）
- 内置 JSON 解析容错：如果 LLM 返回非标准 JSON，尝试正则提取

9. 编写 `backend/core/orchestrator.py`

创建 `Orchestrator` 类：

- `plan(intent, safety_result, context) -> ServicePlan`: 用 Jinja2 渲染 `service_planning.j2`，将可用工具列表 + 安全约束 + 意图传给 LLM，获取工具调用计划
- `execute(plan, context) -> list[ToolResult]`: 按依赖顺序执行工具调用，收集每步结果

10. 编写 `backend/core/output_formatter.py`

创建 `OutputFormatter` 类：

- `format(intent, plan, tool_results, safety_result, context) -> AgentResponse`: 用 `response_generation.j2` 让 LLM 生成自然语言回复，然后组装完整的 `AgentResponse` 结构（5部分：user_response + service_plan + reasoning + forbidden_actions + safety_alerts + follow_up）

11. 编写 `backend/core/agent.py`

创建 `Agent` 类，编排完整的7步流水线：

```
async def process(self, session_id, user_message) -> AgentResponse:
    # Step 1: 获取上下文
    context = self.context_manager.get_context(session_id)
    # Step 2: 意图理解
    intent = await self.intent_engine.analyze(user_message, context)
    # Step 3: 安全检查
    safety = self.safety_engine.check(context.vehicle, context.environment, intent, user_message)
    # Step 4: 服务编排
    plan = await self.orchestrator.plan(intent, safety, context)
    # Step 5: 工具执行
    tool_results = await self.orchestrator.execute(plan, context)
    # Step 6: 输出生成
    response = await self.output_formatter.format(intent, plan, tool_results, safety, context)
    # Step 7: 更新上下文 & 返回
    self.context_manager.add_message(session_id, "user", user_message)
    self.context_manager.add_message(session_id, "assistant", response.user_response)
    return response
```
