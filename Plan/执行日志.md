**产出文件**：`backend/safety/rule_engine.py`（312行）

**核心组件**：

| 组件 | 类型 | 用途 |
|------|------|------|
| `_DotDict` | 内部类 | 将嵌套 dict 包装为支持 dot.notation 属性访问的对象，用于 eval() 条件评估 |
| `build_context()` | 函数 | 将 VehicleState/EnvironmentContext/OrderState/UserProfile 的 model_dump() 组装为规则评估命名空间 |
| `RuleEngine` | 类 | 规则引擎主类，提供加载、检查、消息渲染等功能 |

**RuleEngine 核心方法**：

| 方法 | 用途 |
|------|------|
| `_load_rules()` | 从 rules.json 加载并用 SafetyRuleSet.model_validate() 验证 |
| `reload()` | 热重载规则文件 |
| `_eval_condition()` | 受限 eval() 评估触发条件（禁用 __builtins__，注入 true/false/null） |
| `_render_message()` | 安全模板渲染，缺失变量保留原占位符 |
| `check(context)` | 核心检查：遍历12条规则，返回 (SafetyAlert[], ForbiddenAction[]) |
| `check_vehicle()` | 快捷方法：传入模型 dict，自动构建上下文并检查 |
| `get_hard_rules()` / `get_soft_rules()` | 按类型过滤规则 |
| `get_rule(rule_id)` | 按 ID 查找单条规则 |

**条件评估安全机制**：
- `eval()` 的 `__builtins__` 设为空字典，禁止访问 Python 内置函数
- 注入 `true=True`、`false=False`、`null=None`，兼容 JSON 风格条件表达式
- `_DotDict.__getattr__` 对不存在的属性返回 `None`，避免条件因缺少字段而崩溃

**修复记录**：首次测试时 `eval()` 无法识别 `true`/`false`（JSON 风格布尔值），报 `NameError: name 'true' is not defined`。已通过在 safe_globals 中注入 `true=True, false=False, null=None` 修复。
