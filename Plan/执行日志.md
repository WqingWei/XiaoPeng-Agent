### 7.1 编写 `backend/core/safety_engine.py` ✅

**产出组件**：

| 组件 | 说明 |
|------|------|
| `SafetyEngine` | 加载并校验 `safety/rules.json`，构建规则上下文，逐条执行 12 条规则 |
| `SafetyResult` | 聚合 `safety_level`、`triggered_rules`、`required_actions`、`forbidden_actions` |
| `_ConditionEvaluator` | 基于 Python AST 的白名单条件求值器，不执行任意代码 |
| `UnsafeConditionError` | 非法或超出白名单的规则表达式异常 |

**核心行为**：

- 自动计算所有触发规则中的最高安全等级；无规则触发时返回 `L0`
- 将 `reject`、`warn`、`force`、`alert` 转换为明确的必需动作
- 根据升级配置补充“转人工”和“呼叫 110/120/119”动作
- `reject` 规则生成标准 `ForbiddenAction`，并渲染规则消息中的状态占位符
- 从现有 `VehicleState` 派生儿童座椅、驾驶员是否离座、后排儿童、目标温度等规则字段
- 允许 `intent` 以结构化字典补充订单、媒体、安全事件、剩余里程等运行时上下文
- 从用户消息识别乘客求助信号，供 S04 使用

### 7.2 实现安全条件求值器 ✅

支持正式计划与现有规则需要的表达式：

- 比较：`>`、`>=`、`<`、`<=`、`==`、`!=`
- 逻辑：`and`、`or`、`not`
- 字段路径：如 `driver.fatigue_level`、`vehicle.battery.charging`
- JSON 常量：`true`、`false`、`null`
- S10 续航公式所需的基础算术：`+`、`-`、`*`、`/`
- 缺失字段安全地按“不触发”处理
- 禁止函数调用、下标访问、lambda、私有属性等非白名单语法

### 7.3 更新核心模块导出 ✅

更新 `backend/core/__init__.py`，统一导出：
`SafetyEngine`、`SafetyResult`、`UnsafeConditionError`。

## 步骤八：Agent 核心引擎

**执行时间**：2026-08-06
**执行状态**：✅ 全部完成

### 8.1 上下文与用户画像管理 ✅

**`backend/core/context_manager.py`**：

- 新增 `ConversationMessage` 和 `ConversationContext` Pydantic 模型
- `ContextManager` 按 `session_id` 隔离维护车辆、环境、订单、画像、消息历史和轮次
- 实现 `get_context()`、`add_message()`、`update_vehicle_state()`、`update_order()`、`reset()`、`remove()`
- `reset()` 可加载 8 个场景预设，并清理旧历史、写入场景系统消息
- 状态更新和场景加载使用深拷贝，避免会话之间互相污染
- `prompt_snapshot()` 提供适合注入 LLM 的 JSON 可序列化上下文

**`backend/core/user_profile_manager.py`**：

- 实现用户画像加载、保存、偏好局部更新和近期行程追加
- 使用 Pydantic 重新校验更新值，拒绝未知字段和非法枚举值
- 对外返回独立副本，避免调用方意外修改存储中的画像

### 8.2 Prompt 工程 ✅

**`backend/prompts/system_prompt.py`**：

- `build_system_prompt()` 拼接小鹏 AI 出行服务管家角色定义和 owner/robotaxi 模式
- 从 `ToolRegistry` 动态写入 26 个工具的名称、说明和参数 Schema
- 写入 12 条安全规则摘要、完整 `AgentResponse` JSON Schema
- 写入当前车辆、环境、订单和用户画像状态快照

**`backend/prompts/few_shot_examples.py`**：

- 8 个标准场景各提供 2 组示例（正常案例 + 边界案例）
- 共 16 组对话、32 条 user/assistant 消息
- 每条 assistant 示例均为可通过 `AgentResponse` 校验的完整 JSON
- 提供 `get_few_shot_examples()` 按场景或全量读取

**3 个 Jinja2 模板**：

| 模板 | 用途 | 关键输出 |
|------|------|----------|
| `intent_analysis.j2` | 意图分析 | detected_intent、intent_type、confidence、context_factors |
| `service_planning.j2` | 安全约束下的工具规划 | steps、选择理由、替代方案、确认信息 |
| `response_generation.j2` | 生成面向用户的温暖回复 | user_response |

模板统一启用 `StrictUndefined`，缺少变量时立即报错，避免静默生成残缺 Prompt。

### 8.3 LLM 调用与意图引擎 ✅

**`backend/core/llm_utils.py`**：

- 使用当前 settings 创建百炼 OpenAI 兼容 `ChatOpenAI`
- 意图阶段使用轻量模型，规划/输出阶段使用主模型
- 支持字符串和多内容块响应
- JSON 容错解析支持纯 JSON、Markdown 代码围栏、JSON 前后混合说明文字

**`backend/core/intent_engine.py`**：

- 新增 `IntentResult`：意图、类型、置信度、上下文因素、原始消息、实体
- 使用系统 Prompt、对应场景 Few-shot 和 `intent_analysis.j2` 调用 LLM
- 从消息提取温度、目的地、确认状态等结构化实体
- LLM 调用、网络或 JSON 解析失败时启用本地意图降级，覆盖疲劳、亲子、补能、停车、找车、异常上车点、改目的地、求助、座舱控制等意图

### 8.4 服务编排与工具执行 ✅

**`backend/core/orchestrator.py`**：

- 新增 `OrchestrationPlan`，在 `ServicePlan` 基础上携带工具选择理由、替代方案和确认信息
- 新增 `ToolResult`，记录每步成功状态、输出、错误、跳过状态和执行耗时
- LLM 规划结果会经过后置校验：
  - 丢弃不存在的工具
  - 过滤未知参数并检查必填参数
  - 重排 step_id 并修复依赖关系
  - 未确认时不执行 `modify_order` / `cancel_order`
  - 根据 S05/S06/S07/S08 拦截视频、高速全开车窗、充电中移动、危险上车点订单变更
- 工具按依赖顺序执行；上游失败时自动跳过下游步骤
- 工具异常时回滚到该步骤执行前状态
- 因现有工具使用全局 `ToolContext`，执行器增加异步锁，防止多会话并发串线
- 工具执行完成后将车辆、环境、订单和画像同步回当前会话
- LLM 不可用时，本地降级规划可闭环执行 8 个标准场景

### 8.5 输出格式化 ✅

**`backend/core/output_formatter.py`**：

- 使用 `response_generation.j2` 生成温暖、专业、简洁的自然语言回复
- 严格组装完整 `AgentResponse`：用户回复、服务计划、推理、安全禁止项、安全告警、后续确认
- 将步骤七新增的安全告警结构直接带入最终响应
- LLM 不可用或响应非法时，根据真实工具结果和安全等级生成本地回复，不虚构执行结果

### 8.6 七步 Agent 流水线 ✅

**`backend/core/agent.py`** 实现 `Agent.process()`：

1. 获取会话上下文
2. 分析用户意图
3. 执行安全规则检查
4. 生成服务计划
5. 按依赖执行工具
6. 生成并组装标准输出
7. 更新对话历史、轮次和用户画像

同一 `session_id` 使用异步锁串行处理，防止同一会话的并发消息乱序。

更新 `backend/core/__init__.py`，统一导出 Agent、上下文、意图、编排、
输出、安全和用户画像相关公共类。

### 8.7 步骤七集成增强 ✅

更新 `backend/core/safety_engine.py`：

- `SafetyResult` 新增标准 `safety_alerts`，供 `AgentResponse` 直接使用
- `check()` 可直接接收 Pydantic `IntentResult`
- 从异常上车点意图、用户消息和施工/封路事件自动派生 S08 上车点风险
- 每条触发规则生成已渲染的 `SafetyAlert`，保留处理方和安全等级
